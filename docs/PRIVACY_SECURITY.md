# 隐私与安全说明

本文说明 IslandQuotes 如何处理第三方名句、AI 审查请求、API Key、队列快照和审计日志。部署到学校大屏前，请由管理员按当地法律、学校政策和供应商条款完成评估。

## 1. 信任边界

插件涉及四类参与者：

1. **ClassIsland / 本机插件进程**：保存设置、队列和日志，决定风险流程。
2. **名句来源服务**：提供被审查的第三方引用。
3. **AI 供应商**：接收引用文本与元数据，返回风险分类。
4. **使用者和复核者**：配置供应商并处理中风险内容。

名句来源和 AI 供应商都是独立的第三方。它们的隐私政策、数据保留、跨境传输、日志记录和内容政策不受本插件控制。选择供应商前请阅读其条款。组件设置中关闭「启用 AI 审查」后，引用文本不会发送给任何 AI 供应商。

插件自身没有实现额外的远程遥测或分析服务；但为了实现配置的功能，它会向已配置的名句 API 和 AI 端点发起网络请求。

## 2. 发送给 AI 供应商的数据

当前 AI 审查提示词由系统提示词和用户提示词组成。用户提示词包含以下内容，并用随机标记与不可信数据边界包裹：

- 引用正文 `content`；
- `providerId`、`providerName` 和上游 ID；
- 上游 ID 类型 `upstreamIdKind`；
- 标题 `title`、作者 `author`、出处 `source`、目录/分类 `catalog`；
- 引用抓取时间 `fetchedAt`；
- 随机生成的数据分隔标记。

此外，HTTP 请求还会携带：

- AI 供应商的 Base URL、协议、模型名和请求参数；
- 配置的 API Key（通常放在认证请求头，不放在提示词正文）；
- 管理员配置的额外请求头；
- 供应商在网络层可见的 IP 地址、请求时间、User-Agent 等常规连接信息。

当前提示词构造器没有把完整本地审计日志、`settings.json`、播放队列快照或历史记录整体发送给 AI。它发送的是待审查引用及其元数据。若管理员在自定义系统提示词、引用来源或额外请求头中主动写入其他信息，这些信息也会被发送或持久化；不要这样做。

提示词快速控制（判断严格程度与禁止的主题标签）同样来自 `settings.json` 的运营者配置，会作为系统消息的一部分注入提示词；主题标签名及其提示词说明是唯一随该功能新增的出站文本，仍属于本机配置数据而非待审内容。

### 2.1 测试连接也会发送数据

「测试连接」会向当前活动 AI 供应商发送一条内置的无害引用，以验证端点、密钥和协议。它不会发送学校真实名句，但仍会暴露本机 IP、所用模型、认证凭据和测试时间。测试结果可能被写入审计日志。

### 2.2 名句来源也会看到请求

抓取名句时，名句 API 能看到本机 IP、请求 URL、User-Agent 和查询参数。请在配置自定义查询或路径时避免加入秘密、姓名、学号等信息。来源返回的内容随后可能被发送给 AI 供应商。
## 3. AI 供应商的第三方风险

默认预设为 **OpenAI 兼容**，Base URL、模型和 API Key 均由管理员填写；插件不内置任何匿名公共端点。

所选第三方供应商可能：

- 记录、缓存、审查、复用或用于服务改进所发送的文本；
- 限流、排队、区域封锁或随时下线；
- 产生与机构隐私政策不兼容的数据处理；
- 返回错误、偏差或不可靠的分类结果。

因此：

- 不要把学生姓名、学号、联系方式、健康信息、内部通知或其他敏感内容发送给未经批准的供应商。
- 需要更强控制时优先使用本地 Ollama，或使用机构已批准并签约的可信 AI 供应商。

## 4. API Key 的存储

### 4.1 直接填写

如果 API Key 直接填写到供应商设置，它会以 **普通文本** 写入插件配置目录的 `settings.json`（JSON 字段为供应商配置中的 `apiKey`）。插件没有使用 Windows Credential Manager、DPAPI 或自建加密：

- 任何能读取该文件的用户、备份程序或同步工具都可能看到密钥；
- `settings.json` 可能被误上传到网盘、代码仓库或工单；
- 界面上的密码掩码只防止旁观，不提供加密。

建议把配置目录视为敏感目录，限制 ACL，不要纳入漫游配置/网盘/版本控制。

### 4.2 `env:NAME` 引用

在 API Key 字段填入 `env:OPENAI_API_KEY` 时，插件保存的是引用文本，并在运行时从进程环境变量读取真实值。这样可以避免把密钥直接写进 `settings.json`，但仍有边界：

- 能读取进程环境或调用进程信息的特权程序可能看到值；
- ClassIsland 的启动方式必须能继承该环境变量；
- 环境变量不存在时，密钥按空处理，测试/审查失败；
- 不要将 `env:` 变量名本身加入日志或截图以外，也不要让无关脚本继承不必要的密钥。

环境变量不是绝对安全区，但通常优于把长期密钥明文写入配置。

### 4.3 额外请求头中的秘密

额外请求头 JSON 可能包含认证信息。把 secret 放到 `extraHeadersJson` 会使其进入 `settings.json`，而且字段名若不是 `apiKey`、`authorization`、`token`、`secret`、`cookie`、`password` 等敏感名称，日志脱敏未必能识别。**不要把额外请求头当作安全密钥库。**

## 5. 本地存储的数据

插件配置目录中可能包含以下文件：

| 文件 | 内容 | 敏感性 |
| --- | --- | --- |
| `settings.json` | AI 供应商配置、Base URL、模型、API Key/`env:` 引用、额外请求头、系统提示词、判断严格程度、禁止主题标签、审查策略、日志保留设置 | 高；可能有明文密钥 |
| `review-queue.json` | 待复核、播放队列、历史和待审查/已审查引用；只保存恢复所需字段，完整请求体、提示词与原始响应不写入该文件（诊断信息在审计日志中） | 高；含第三方引用和 AI 输出的风险理由/分类 |
| `log\audit-yyyy-MM-dd.jsonl` | 请求、审查、决策、人工复核、播放、队列恢复和错误事件 | 高；可能含引用正文、提示词、响应摘要和上游 URL |
| 队列快照损坏备份 | 损坏的 `review-queue.json` 副本，用于恢复与审计 | 高；继承原快照内容 |

快照、日志与「历史记录」页都会保留高风险条目的正文。需要彻底清除时，应按下文的数据清理步骤处理所有相关文件，而不是只清空界面。

### 5.1 日志中的脱敏

审计日志服务会：

- 对字段名包含 `key`、`token`、`authorization`、`secret`、`cookie`、`password` 的对象属性写入 `[REDACTED]`；
- 用正则替换 `authorization`、`x-api-key`、`x-goog-api-key`、`api_key`、`access_token`、`refresh_token`、`secret`、`cookie`、`password` 等赋值；
- 替换形如 `Bearer <长值>` 的文本。

但脱敏是纵深防御，不是对任意日志文本的完全保证。模型可能把敏感片段写进自由文本，URL 查询参数也可能包含签名，管理员不应公开分享未审查日志。

### 5.2 日志完整提示词/响应开关

`LogFullPrompts` 和 `LogFullResponses` 可控制是否保留完整提示词与响应；默认开启以便排查。若学校对数据留存敏感：

1. 关闭完整提示词/响应；
2. 只保留必要的请求 ID、风险、决策和错误摘要；
3. 将保留天数调低；
4. 定期检查并清理 `log\`。

关闭日志不影响风险判决，但会降低可审计性。
## 6. 失败关闭与风险状态

审查流程遵循失败关闭（fail-closed）原则：

- 请求超时、HTTP 错误、限流、空响应、无效 JSON、缺少字段、未知风险或解析异常，都会得到 `IsSuccess=false` / `Risk=Unknown`。
- 失败条目 **不会被视为 Low，也不会自动播放**。
- 默认策略是转人工复核；也可在 AI 设置页改为直接拦截。
- 本地忽略词命中会直接标记为高风险并拦截，即使 AI 返回 Low。
- 高风险条目不会进入待复核批准列表。

失败关闭只能保护「不因 AI 故障而自动放行」，不能保证某个通过项在语义上绝对安全。供应商返回 Low 也可能误判。

## 7. 高风险内容掩码

实现中的安全展示约束：

- 组件只接收队列服务判定为 Approved 并已从播放队列取出的条目。
- Medium 只有在人工批准后才会变成 Approved。
- High 和 Blocked 不进入播放队列。
- 「历史记录」页完整显示高风险/Blocked 条目的正文、署名、供应商、上游 ID、时间和风险理由，便于审计；这些条目不会进入播放队列。
- 队列恢复时，`Reviewing`/`Pending` 会转为待人工复核，不会因程序中断变成可信内容。

掩码是展示层保护，不删除持久化文件中的原始字段。需要数据彻底删除时必须清理队列快照、备份和日志。

## 8. 提示词注入与内容边界

引用文本、作者和元数据均被当作不可信第三方数据。默认系统提示词要求模型不执行引用中的指令、不改变 JSON 格式、不把不确定内容判为 Low，并把试图操纵审查器的内容视为可疑。

但这不能消除所有风险：

- 模型可能不遵守提示词；
- 第三方名句可能包含隐晦、双关、图像化或无上下文才有害的内容；
- 模型可能产生偏差或错误置信度；
- 供应商可能更新模型而改变分类行为；
- 自定义系统提示词或来源选项可能削弱预期效果。

因此人工复核仍然是必要环节。不要把 `confidence` 当作数学保证，也不要把 AI 审查当成学校内容审核制度的替代品。

## 9. 安全使用清单

- [ ] 优先为本插件选择本地 Ollama 或机构批准的可信供应商。
- [ ] 不向未经批准的供应商发送敏感、内部或可识别个人信息。
- [ ] API Key 优先使用 `env:NAME`，并限制配置目录 ACL。
- [ ] 不把 `settings.json`、`review-queue.json`、日志或包含密钥的截图提交到仓库/工单/聊天。
- [ ] 按需关闭完整提示词和完整响应日志，缩短保留期。
- [ ] 定期核查高风险拦截、AI 失败和人工批准记录。
- [ ] 不删除失败关闭策略来追求「不打扰」。
- [ ] 升级或更换模型后重新做连接测试并抽样验证分类。
- [ ] 发现密钥泄露时先 **撤销/轮换**，再排查日志、备份和部署环境；仅修改界面字段不足以消除已泄露风险。

## 10. 数据清理与卸载

清理前请先备份必要的审计证据，并关闭 ClassIsland，避免文件正在写入。

1. 打开插件配置目录，记录当前设置和需要保留的审计记录。
2. 删除 `log\audit-*.jsonl` 中不再需要的日志；如使用队列快照，删除 `review-queue.json` 及其损坏备份。
3. 如需彻底移除密钥，删除 `settings.json` 中的供应商配置或删除整个 `settings.json`；同时撤销提供商侧的对应密钥。
4. 从系统环境变量/ClassIsland 启动脚本中移除不再使用的 `env:NAME` 值。
5. 通过 ClassIsland 插件管理卸载 CIPX。
6. 检查备份、同步目录、回收站和工单附件是否仍包含旧配置或日志。

删除队列/设置后重新启用会回到安全默认：默认 OpenAI 兼容预设（需重新填写地址与密钥），AI 失败转人工复核。生产部署请按机构流程恢复批准过的供应商配置。
